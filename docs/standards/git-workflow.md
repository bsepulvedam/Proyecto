# Flujo Git

Partir de `main` sincronizada y árbol conocido. Rama corta por objetivo; commits pequeños solo cuando el usuario los autorice. Revisar status/diff, tests y secretos antes de integrar. No reescribir ramas compartidas. Migraciones se integran en orden y conflictos de `down_revision` se resuelven conscientemente. Release con tag, notas, backup y rollback documentado.
